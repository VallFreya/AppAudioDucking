# Файлы плагина, журнал и формат config.json

## Где что лежит

| Что | Где |
|---|---|
| Настройки (фильтры, названия, цели, тема) | `%APPDATA%\obs-studio\plugin_config\SmoothMuterPlugin\config.json` |
| Копия нечитаемого конфига (появляется только при ошибке чтения) | `config.json.broken` рядом с конфигом |
| Файл восстановления громкости (только на время приглушения) | `%APPDATA%\obs-studio\plugin_config\SmoothMuterPlugin\ducked_volumes.txt` |
| Журнал плагина | `%LOCALAPPDATA%\Temp\ProcessMuter_debug.log` |

## Журнал: что искать

В журнал пишутся загрузка плагина, обновление фильтров, привязка к источникам и моменты приглушения и возврата звука.

| Запись или симптом | Что значит и что делать |
|---|---|
| `OBS source '...' not found` | Источника с таким именем нет в OBS. Выберите в фильтре существующий источник |
| Нет записей `Mute`, хотя в источнике есть звук | Уровень не достигает порога. Поднимите порог (например, с -60 до -40 дБ) |
| Приложение остаётся приглушённым в тишине. Каждые 15 секунд пишется `Still muted ... -58,9dB > -60,0dB` | Фоновый шум источника выше порога. Поднимите порог выше этого уровня (например, до -45 дБ) |
| Звук «дёргается» (то глушится, то возвращается) | Увеличьте **Задержку возврата**. В журнале видно, через сколько мс после тишины был `Unmute` |
| `Mute` есть, но громкость приложения не меняется | Проверьте имя процесса (как в Диспетчере задач, без `.exe`). Приложение должно играть звук через устройство вывода по умолчанию |
| `Config file ... is not valid` | `config.json` не читается. Копия сохранена в `config.json.broken`, исправьте её и верните на место |

## Формат config.json

Файл можно править вручную (OBS при этом лучше закрыть).

```json
{
  "version": 2,
  "theme": "dark",
  "filters": [
    {
      "name": "Музыка при разговоре",
      "enabled": true,
      "scene_name": "Игра",
      "source_name": "Микрофон",
      "target_type": "process",
      "process_name": "chrome",
      "target_scene": "",
      "target_source": "",
      "threshold_db": -45,
      "duck_db": -60,
      "duck_percent": 20,
      "restore_custom": true,
      "restore_db": 0,
      "restore_percent": 60,
      "fade_ms": 600,
      "hold_ms": 1500
    },
    {
      "name": "Фоновая музыка в OBS",
      "enabled": true,
      "scene_name": "Игра",
      "source_name": "Микрофон",
      "target_type": "obs_source",
      "process_name": "",
      "target_scene": "Игра",
      "target_source": "Музыка",
      "threshold_db": -50,
      "duck_db": -24,
      "duck_percent": 0,
      "restore_custom": true,
      "restore_db": -12,
      "restore_percent": 100,
      "fade_ms": 400,
      "hold_ms": 1500
    }
  ]
}
```

| Поле | Значение |
|---|---|
| `theme` | `dark` (по умолчанию) или `light` |
| `name` | Название фильтра. Пустое заменяется на «Фильтр N» |
| `enabled` | `false` выключает фильтр: он остаётся в файле и в окне, но ничего не глушит. По умолчанию `true` |
| `scene_name`, `source_name` | Что отслеживаем. Пустая сцена означает глобальные источники |
| `target_type` | `process` (поле `process_name`) или `obs_source` (поля `target_scene` и `target_source`). Оба набора полей хранятся всегда |
| `process_name` | Имя процесса без `.exe` (расширение отбрасывается) |
| `threshold_db` | Порог срабатывания в дБ, от `-60` до `0` |
| `duck_db` / `duck_percent` | Уровень приглушения: в дБ для источника OBS (от `-60` до `0`, `-60` это тишина), в процентах для процесса (от `0` до `100`). Используется поле, соответствующее `target_type`. Уровень абсолютный, не доля от исходной громкости |
| `restore_custom` | `false` (по умолчанию): возвращать до исходной громкости, `restore_*` игнорируются. `true`: возвращать до заданного уровня |
| `restore_db` / `restore_percent` | Уровень возврата (дБ для OBS, проценты для процесса). Можно выше исходной громкости, но не ниже уровня приглушения |
| `fade_ms` | Время затухания, от `1` до `60000` мс |
| `hold_ms` | Задержка возврата, от `0` до `3600000` мс |

Значения вне границ при чтении подтягиваются к ближайшей границе (порог `-75` станет `-60`, `5` станет `0`). Файлы старых версий читаются без изменений: отсутствующие поля получают значения по умолчанию, а настройки самой первой версии (один источник и один процесс) превращаются в один фильтр.

# Сборка, тесты и структура проекта

## Сборка из исходников

Нужны:

- [.NET SDK 10](https://dotnet.microsoft.com/download) (версия из `SmoothMuterPlugin.csproj`);
- Visual Studio с компонентом **«Разработка классических приложений на C++»** (компоновщик NativeAOT);
- Git.

```bash
git clone https://github.com/VallFreya/AppAudioDucking.git
cd AppAudioDucking
dotnet publish -c Release -r win-x64
```

Готовая библиотека: `bin\Release\net10.0-windows\win-x64\publish\SmoothMuterPlugin.dll`. Скопируйте её в папку плагинов OBS (`<папка OBS>\obs-plugins\64bit`) при закрытом OBS и запустите его.

Если компоновщик не находит `vswhere.exe`, соберите из «Developer PowerShell for VS» или добавьте `C:\Program Files (x86)\Microsoft Visual Studio\Installer` в `PATH`.

## Тесты

Проверки лежат в `tests/ProcessMuter.Tests` (xUnit). Исходники плагина подключаются в них напрямую, OBS не нужен:

```bash
cd tests/ProcessMuter.Tests
dotnet test
```

Около 260 проверок, прогон занимает около минуты. Тесты окна открывают настоящие окна, поэтому им нужен рабочий стол Windows; проверки с аудио пропускаются, если нет устройства вывода. Все файлы тесты пишут во временную папку, настоящие `config.json` и журнал не затрагиваются.

| Файл | Что проверяется |
|---|---|
| `EngineTests.cs` | Логика приглушения на модели цели: задержка возврата, дребезг, громкость выше 1, абсолютные уровни, новые сессии, сбои звуковой подсистемы, огромные и отрицательные времена |
| `EngineFuzzTests.cs` | Случайные последовательности событий: после выгрузки каждая сессия возвращается к исходной громкости, в процессе громкость не выходит за границы |
| `AggregationTests.cs` | Как несколько фильтров на одну цель сводятся в одно решение |
| `ConfigTests.cs` | Крайние значения, ввод чисел, испорченный, обрезанный, пустой и старый `config.json` |
| `StorageTests.cs` | Атомарная запись, файл восстановления, чтение и запись конфига, копия `.broken`, таймер плагина при исключениях, нагрузка из многих потоков |
| `PreviewEngineTests.cs` | Прослушивание ползунка вместе с настоящим приглушением, восстановление после аварии |
| `ProbeAndPreviewTests.cs` | Предпросмотр, измерители и аудиосессии на несуществующих целях и странных значениях |
| `AudioSessionTests.cs` | Настоящие аудиосессии Windows (тестовый процесс сам играет тишину) |
| `UiTests.cs`, `ControlTests.cs` | Окно и контролы: 100 фильтров, огромные названия, любые размеры окна, мусор в полях, автосохранение при сбоях записи, утечки дескрипторов |

Папка `tests` исключена из компиляции плагина в `SmoothMuterPlugin.csproj`, в DLL она не попадает.

## Структура проекта

| Файл / папка | Назначение |
|---|---|
| `Plugin.cs` | Точка входа плагина: регистрация в OBS, загрузка и выгрузка, чтение и запись конфига |
| `PluginConfig.cs` | Модель конфига: фильтры, тема, миграция старого формата |
| `AudioMutesManager.cs` | Следит за источниками всех фильтров (volmeter OBS) и передаёт решение в `DuckingEngine` |
| `DuckingEngine.cs` | Когда приглушать и возвращать громкость, плавное затухание, задержка возврата, восстановление после аварии |
| `ProcessAudioControl.cs` | Аудиосессии процесса и список запущенных процессов (Core Audio API) |
| `ObsSourceBackend.cs` | Цель «звуковой источник OBS», выбор цели по ключу, файл восстановления громкости |
| `ObsSceneApi.cs` | Список сцен OBS и звуковых источников сцены |
| `AtomicFile.cs` | Запись файла через временный |
| `SettingsForm.cs` | Окно настроек |
| `LevelSlider.cs`, `LevelProbes.cs`, `VolumePreview.cs` | Индикаторы уровня, живые измерители, прослушивание ползунков |
| `ThemedControls.cs`, `ThemedWidgets.cs`, `ThemedDialog.cs` | Собственные контролы в стиле OBS |
| `ObsTheme.cs`, `Ui.cs`, `Loc.cs` | Темы, масштаб и шрифты, тексты на русском и английском |
| `docs/` | Документация и скриншоты |
| `tests/ProcessMuter.Tests/` | Автоматические проверки |
| `SmoothMuterPlugin.csproj` | Файл проекта |
